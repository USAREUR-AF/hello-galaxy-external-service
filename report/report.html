1. Declare

One YAML file, examples/hello-external.zagros.yml, is the whole goatnet-side footprint. tools/validate-declaration.py applies the goatnet's own rules and previews what it derives: the hostname, the issuer with its trailing slash, the JWKS URL, the OAuth2 client, the edge route and certificate name, the DNS record and the status row. Three refusals follow: a LAN backend, a door outside the closed set, a passed retire_after.

4. A platform with several endpoints

One declaration can carry several endpoint names through hostnames:, and tls: decides who terminates. In edge mode the goatnet publishes one route carrying every name and puts every name on its own certificate. In partner mode it publishes DNS records pointing at the owner's host and nothing else at all — no route, no backend, no certificate — so reachability control moves to that host. Every hostname is one DNS label; the mesh zone does not nest.

── Step 1 ─ The setting
A goatnet runs an identity plane: people sign in once at the site's Ory Hydra
and get an id_token that names them (sub, email, groups, and on some goatnets
aff.id, their organisation). Core services on the management host use it.
An EXTERNAL service is one the goatnet does not build or deploy: it runs on its own
host, is not core, and is often temporary — an event registry, a demo.
It still wants goatnet sign-in, a name on the goatnet's edge, and a status row.

── Step 2 ─ The three things this repo shows
  • declare:   one YAML file is the service's whole goatnet-side footprint  (scenario 01)
  • verify:    the service checks the goatnet's tokens itself and authorizes
  •            from its own roster; claims grant nothing on their own  (scenario 02)
  • withdraw:  the same file, marked enabled: false, and a check refuses any
  •            stray reference to the service's name elsewhere  (scenario 03)

── Step 3 ─ The trust rule
The provider authenticates. The service authorizes. A token's claims are
evidence, never a grant: the service decides from its own records.

── Step 4 ─ Why the fence lives on the service's host
The host joins the mesh in the EXTERNAL-INFRA tier, which every role group
reaches directly. A fence on the management host in front of it would be a
fence with a gap beside it. So the service (or an oauth2-proxy beside it)
verifies signature, issuer, audience and expiry on every request, and binds
its mesh IP, never 0.0.0.0.

── Step 5 ─ The boundary rule
A temporary service's name may appear in the goatnet's configuration ONLY in
its own declaration file. A CI check fails any change that names it anywhere
else. That is what makes withdrawal complete rather than hopeful.

── Step 6 ─ Prerequisites
  ✓ python3 + curl + PyJWT/cryptography/PyYAML present
  ⓘ honesty: the issuer used by scenario 02 is SIMULATED (local-issuer/); the apply step,
  ⓘ honesty: the edge and the checks run on the goatnet — docs/honesty-matrix.md grades each piece.

── Step 7 ─ What's next

  • 02-sign-in-and-authorize   start the issuer + service, walk every rule with real tokens
  • 03-withdraw                mark it withdrawn; see what is removed; run the footprint check
